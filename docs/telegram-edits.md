# Правки сайту з Telegram

Даша (чи Олексій) пише в тему правок робочого чату як колезі — текстом, скріном,
голосовим. Агент Claude сам розбирається, що мається на увазі, вносить правку в
код, і вона з'являється на **тестовій** версії сайту. На babaka.shop правки
виходять лише **пакетом** — через випуск, який підтверджує Олексій. На сайт іде
платний трафік, тож помилка в тексті чи верстці коштує грошей.

```
повідомлення в темі правок (текст / фото / альбом / голосове / кружечок)
  → /api/telegram/webhook (kudos-web, лише Production)
  → нова GitHub issue з міткою telegram-edit або коментар до відкритої
  → .github/workflows/telegram-edit.yml: розшифровка голосових (faster-whisper) → Claude у гілці tg/<N>
  → перевірка меж + typecheck/test/build → PR tg/<N> → dasha-edits, автозлиття на зеленому CI
  → Vercel Preview гілки dasha-edits
  → telegram-notify.yml: «Готово на тесті ✅ <посилання>» реплаєм
…
«випускай» / /випуск (будь-який редактор) → PR dasha-edits → main + «Олексій, випускаємо? так / ні»
  → «так» Олексія реплаєм → злиття на зеленому CI → «Вийшло на сайт ✅»
```

## Як писати боту

Префікс не потрібен: **будь-яке** повідомлення редактора в темі правок — звернення
до бота. Текст, фото (з підписом чи без), скрін файлом, альбом, голосове, аудіо,
кружечок.

Куди воно потрапить:

1. **Реплай на повідомлення бота з `#N`** — доповнення до правки #N (якщо вона ще
   відкрита; закрита — буде нова правка).
2. **Нове повідомлення, а в тебе є відкрита правка, де бот спитав і чекає
   відповіді** — це відповідь туди. Тому на питання бота можна відповідати просто
   наступним повідомленням, навіть «так», «ок» чи «1».
3. **Нове повідомлення протягом ~20 хв після останньої активності по твоїй
   відкритій правці** — доповнення до неї («і ще кнопку зеленою»).
4. Інакше — нова правка, бот відповідає «Прийняв, #N 👌» (на голосове — «Слухаю 🎧, #N»).

Склеюються лише повідомлення **того самого** автора. Коротке «ок», «дякую», «👍»
без питання бота нікуди не йде (бот мовчить). Хочеш точно нову правку, а не
доповнення — почни з `правка:` (стара форма, лишилась для цього).

**Альбом** із кількох фото — одна правка: перше фото створює issue і відповідає
в тему, решта мовчки дописуються туди ж (`media_group_id`, замок у Blob
`telegram/groups/<id>/`).

**Голосові** (voice, audio, кружечок) вебхук лише зберігає в Blob
(`edits/<issue>/<msg>.ogg|mp3|m4a|mp4`) і одразу відповідає «Слухаю 🎧, #N» —
на розшифровку не чекає. Розшифровує воркфлоу перед запуском агента:
faster-whisper на CPU раннера, безкоштовно й без секретів (модель `medium`,
інша — змінною `WHISPER_MODEL`, кешується через `actions/cache`). Мова
визначається сама, а якщо модель не впевнена — українська. Розшифровка
додається в issue коментарем «🎙 Розшифровка: …» (у Telegram не дублюється) і
йде агенту. Кожне голосове розшифровується один раз (позначка `transcript:`).

## Команди

| Що написати | Хто | Що станеться |
|---|---|---|
| будь-що (див. вище) | редактори | нова правка або доповнення до відкритої |
| `правка: …` | редактори | завжди нова правка |
| `/відкат` | редактори | відкат останньої правки **в dasha-edits** (main не чіпається) |
| `/випуск`, «випускай», «викладай на сайт», «заливай в прод» | редактори | PR dasha-edits → main і питання Олексію, див. «Випуск» |
| `так` / `ні` реплаєм на «Випускаємо?» | лише перший id у `TELEGRAM_EDITORS` (Олексій) | злиття випуску / скасування |
| `/id` | будь-хто в темі | бот відповідає «твій user_id: …» |

Усе інше: повідомлення в інших темах (зокрема «Реклама», 88), в інших чатах і
від людей не зі списку `TELEGRAM_EDITORS` бот ігнорує мовчки. Чужі команди
(`/start` тощо), стікери й службові повідомлення — теж.

## Як думає агент

- Розуміє скорочене «як людина»: сам шукає в коді й на живому сайті, що мається
  на увазі, додумує очевидне й обирає розумний варіант за замовчуванням. Якщо
  щось додумав — коротко пише, що саме обрав.
- Перепитує лише коли без відповіді справді не можна, і тоді — одне конкретне
  питання з варіантами, на яке можна відповісти одним словом. Такий коментар
  має позначку `<!-- claude-question -->`: за нею вебхук знає, що наступне
  повідомлення — відповідь.
- Питання, а не правка («а скільки коштує доставка?», «де змінити ціну?») — агент
  відповідає в тему, нічого не комітить і закриває issue.
- Правка поза межами — не сухе «ні», а пояснення простими словами (і де це
  змінити, якщо це адмінка) з тегом Олексія. У Telegram тег справжній:
  вебхук кладе user_id Олексія в tg-блок issue (`owner`).
- «Дякую» / «ок» без нового прохання — агент нічого не робить і мовчить.

## Що агент може і чого не може

Агенту дозволено змінювати тексти, верстку, стилі, зображення й компоненти вітрини в `apps/web`.

Без Олексія агент нічого не змінює, а пояснює коментарем і тегає Олексія; повідомлення приходить у тему:

- міграції БД, `apps/api` (замовлення, оплати Monobank), `packages/contracts`;
- авторизацію та адмінку;
- env, секрети, `.github`;
- видалення сторінок чи даних;
- robots, sitemap та індексацію;
- аналітику й теги (GA4, Google Ads);
- ціни в коді та оформлення замовлення.

Вміст з адмінки чи БД агент у коді не змінює. Натомість він пише, де саме в адмінці це поправити.

Межі тримаються не лише на інструкції агенту:

- в агента немає git. Коміт, пуш і PR робить воркфлоу, і лише в `tg/<N>` → `dasha-edits`;
- крок «Перевірка меж» зупиняє правку, якщо змінено файли поза дозволеними, щось видалено або схоже на зміну цін. Тоді нічого не пушиться, а Олексій отримує коментар із тегом;
- агент слухає лише тіло issue й коментарі власника репо (вебхук пише через PAT Олексія); фото й голосові з чужих коментарів воркфлоу не завантажує;
- перед пушем запускаються typecheck, тести й build, а після пушу ще раз CI на PR. PR автоматично зливається лише на зеленому CI.

## Випуск на сайт

1. Будь-який редактор пише `/випуск` або природною фразою: «випускай»,
   «викладай на сайт», «заливай в прод» (лише коротке повідомлення цілком:
   «випускай нову кнопку» — це правка, не випуск).
2. `telegram-release.yml` (`prepare`) створює чи оновлює PR dasha-edits → main
   і пише в тему, що піде на сайт, з тегом Олексія:
   «Олексій, випускаємо? Відповідай реплаєм «так» або «ні». (PR #M, версія abc1234)».
3. **Лише реплай Олексія** (перший id у `TELEGRAM_EDITORS`) на це повідомлення:
   - «так» / «ок» / «✅» / «👍» → `merge`: воркфлоу зливає PR через `EDITS_GH_PAT`
     (merge commit), але тільки якщо PR досі dasha-edits → main, його голова —
     саме та версія, про яку питали (нові правки після питання → «напиши ще раз»),
     CI на PR зелений (ще йде — чекає до ~30 хв; червоний — не зливає й пояснює)
     і немає конфлікту. Далі «Злив 🚀», а після деплою — «Вийшло на сайт ✅ https://babaka.shop»;
   - «ні» / «❌» → `cancel`: PR закривається, «випуск скасовано», правки лишаються на тесті;
   - щось інше → «Відповідай «так» або «ні»».
4. «Так» від будь-кого іншого бот не виконує: «Чекаємо на відповідь Олексія».

Автозлиття в main немає: без «так» Олексія main не змінюється. Злити PR
випуску руками теж можна.

## Тестова версія (Preview)

Preview `kudos-web` дивиться в **продовий** API: ту саму базу й той самий
Monobank (`API_ORIGIN` однаковий для Production і Preview). Тому на Preview:

- `apps/web/src/middleware.ts` блокує все, що не GET, до `/api/v1/*`.
  Виняток — розрахунок кошика (`POST /cart/quote`), бо він нічого не записує.
  Замовлення, оплата, заявки, події статистики й вхід в адмінку на Preview не працюють;
- кнопка «Замовити» неактивна, а вгорі видно плашку «Тестова версія сайту»;
- GA4, Google Ads і власна статистика не вантажаться, щоб тестові кліки не потрапили в кампанії;
- `noindex`: заголовок `X-Robots-Tag` на всіх відповідях, `robots.txt` → `Disallow: /`, метатег robots;
- вебхук Telegram відповідає 404: він живе лише в Production.

Стабільна адреса тесту: `https://kudos-web-git-dasha-edits-devvoronin-gmailcoms-projects.vercel.app`
(впиши її в змінну `DASHA_PREVIEW_URL`, щоб у Telegram завжди йшло це посилання).

## Гілки

| Гілка | Що це |
|---|---|
| `main` | сайт. Лише PR; випуск з Telegram зливається тільки після «так» Олексія (або руками). Автозлиття заборонене |
| `dasha-edits` | збірка правок з Telegram. Сюди йдуть **тільки** PR з Telegram, з автозлиттям на зеленому CI. Не видаляти |
| `tg/<N>` | робоча гілка агента для issue #N |
| `revert/<N>-<run>` | відкат правки #N |
| `sync/main-<sha>` | злиття main у dasha-edits після кожного пушу в main |

## Мітки

- `telegram-edit`: issue з Telegram (саме мітка запускає агента) і PR агента;
- `on-preview`: про цей PR уже написали «Готово на тесті»;
- `reverted`: PR правки, який відкотили через `/відкат`.

## Секрети та змінні

**Vercel → kudos-web → Settings → Environment Variables, лише Production:**

| Змінна | Значення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота (той самий бот) |
| `TELEGRAM_WEBHOOK_SECRET` | випадковий рядок `[A-Za-z0-9_-]`, той самий передається в setWebhook |
| `TELEGRAM_EDITS_CHAT_ID` | `-1004296608260` |
| `TELEGRAM_EDITS_THREAD_ID` | id теми правок (не 88!) |
| `TELEGRAM_EDITORS` | user_id через кому, **першим іде Олексій** (лише він підтверджує випуск) |
| `TELEGRAM_GITHUB_TOKEN` | fine-grained PAT, див. нижче |
| `TELEGRAM_GITHUB_REPO` | необов'язково, за замовчуванням `ol-voronin/kudos` |

`BLOB_READ_WRITE_TOKEN` уже є: його використовують фото й голосові правок
(`edits/<issue>/<msg>.<ext>`), позначки ідемпотентності (`telegram/updates/<update_id>.txt`)
і замки альбомів (`telegram/groups/<media_group_id>/`).

**GitHub → Settings → Secrets and variables → Actions:**

| Тип | Назва | Для чого |
|---|---|---|
| secret | `EDITS_GH_PAT` | PR, коментарі й пуші від воркфлоу. Без PAT не запуститься CI на PR і не прийдуть сповіщення |
| secret | `TELEGRAM_BOT_TOKEN` | повідомлення в тему |
| secret | `TELEGRAM_WEBHOOK_SECRET` | те саме значення, що в Vercel; ним воркфлоу «Telegram setup» реєструє вебхук |
| secret | `ANTHROPIC_API_KEY` або `CLAUDE_CODE_OAUTH_TOKEN` | агент Claude |
| variable | `TELEGRAM_EDITS_THREAD_ID` | id теми правок («Покращення сайту») |
| variable | `TELEGRAM_EDITS_CHAT_ID` | необов'язково: за замовчуванням `-1004296608260` |
| variable | `DASHA_PREVIEW_URL` | стабільна адреса тесту (необов'язково) |
| variable | `WHISPER_MODEL` | модель розшифровки голосових (необов'язково, за замовчуванням `medium`; швидше — `small`) |

**PAT** (fine-grained, тільки репозиторій `ol-voronin/kudos`): Contents RW, Pull requests RW,
Issues RW, Actions RW, Workflows RW (sync переносить у dasha-edits і зміни `.github`).
Той самий PAT підходить і для `TELEGRAM_GITHUB_TOKEN` у Vercel.

## Увімкнути / вимкнути

Найпростіше — воркфлоу **Telegram setup** (Actions → Telegram setup → Run workflow):

- `discover` — до ввімкнення вебхука показує теми чату й людей, що писали за добу:
  звідти `TELEGRAM_EDITS_THREAD_ID` і `TELEGRAM_EDITORS` (напиши щось у темі перед запуском);
- `set` — увімкнути вебхук; `info` — стан; `delete` — вимкнути.

Токен береться з secrets і ніде не виводиться. Те саме локально:

```bash
# увімкнути (значення ті самі, що в Vercel Production)
TELEGRAM_BOT_TOKEN=… TELEGRAM_WEBHOOK_SECRET=… node scripts/telegram-webhook.mjs set
# стан
TELEGRAM_BOT_TOKEN=… node scripts/telegram-webhook.mjs info
# вимкнути
TELEGRAM_BOT_TOKEN=… node scripts/telegram-webhook.mjs delete
```

`deleteWebhook` вимикає лише читання теми правок. Щоденний звіт у тему
«Реклама» працює як і раніше: він лише викликає `sendMessage`.

Щоб тимчасово зупинити агента, не чіпаючи бота, вимкни воркфлоу *Telegram edit*
в Actions (⋯ → Disable workflow).

## Файли

- `apps/web/src/app/api/telegram/webhook/route.ts` — вебхук;
- `apps/web/src/features/telegram-edits/*` — розбір повідомлень (`parse.ts`: що це за повідомлення, склейка, випуск), GitHub, Telegram, Blob (`storage.ts`: файли, ідемпотентність, альбоми);
- `apps/web/src/middleware.ts`, `apps/web/src/lib/deploy-env.ts` — захист Preview;
- `.github/workflows/telegram-{edit,notify,release,revert,setup,ping}.yml` (`telegram-release` — підготовка, злиття й скасування випуску), `sync-dasha-edits.yml` (`telegram-ping` — ручний пуш від Claude у тему правок);
- `.github/workflows/automerge-dasha-edits.yml` — злиття PR `tg/`, `revert/`, `sync/` у dasha-edits на зеленому CI (не залежить від правил захисту гілок);
- `.github/scripts/telegram.cjs` — відправка в тему з Actions (відмовляється писати в тему 88; `{{owner}}` → тег Олексія);
- `.github/scripts/transcribe.py` + `transcribe-requirements.txt` — розшифровка голосових (faster-whisper);
- `scripts/telegram-webhook.mjs` — setWebhook / getWebhookInfo / deleteWebhook.
